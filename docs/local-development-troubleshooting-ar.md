# دليل حل مشاكل التشغيل المحلي

يشرح هذا الدليل تشخيص أخطاء تشغيل الواجهة والـAPI محليًا، وخصوصًا:

```text
connect ECONNREFUSED 127.0.0.1:4000
```

## كيف يعمل تشغيل المشروع؟

من مجلد المشروع الرئيسي، يشغّل الأمر:

```powershell
npm run dev
```

خدمتين بالتوازي:

- واجهة React وVite على `http://localhost:5173`.
- واجهة الـAPI على `http://127.0.0.1:4000`.

تُرسل الواجهة طلبات `/api` عبر وسيط Vite إلى الـAPI. عنوان الوسيط الافتراضي هو `http://127.0.0.1:4000`، ويمكن ضبطه في `.env` من خلال `VITE_DEV_API_TARGET`.

## ماذا يعني `ECONNREFUSED`؟

يعني أن البرنامج حاول الاتصال بعنوان ومنفذ، لكن لم يجد خدمة تستقبل الاتصال هناك. في هذا المثال، لم يجد العميل الـAPI على المنفذ `4000`.

لا يثبت هذا الخطأ وحده أن عنوان الـAPI غير صحيح؛ قد يكون الـAPI لم يبدأ، أو بدأ ثم توقف بسبب خطأ، أو أن العملية التي تشغّله أُغلقت.

## السبب الذي ظهر في هذا المشروع

عند إعادة تشغيل `npm run dev` بينما توجد نسخة أخرى من المشروع تعمل، قد يكون المنفذ `5173` مستخدمًا بالفعل. عندها يعرض Vite خطأ مثل:

```text
Error: Port 5173 is already in use
```

سكربت التشغيل الرئيسي مضبوط على إيقاف الخدمة الأخرى إذا فشلت إحداهما (`--kill-others-on-fail`). لذلك قد يؤدي فشل Vite بسبب المنفذ المشغول إلى إيقاف الـAPI أيضًا. بعد توقف الـAPI، يؤدي أي طلب إليها على `127.0.0.1:4000` إلى `ECONNREFUSED`.

## الحل الأول: أوقف التشغيل السابق

1. ارجع إلى الطرفية التي تشغّل المشروع.
2. اضغط `Ctrl+C` لإيقافه، وانتظر حتى تنتهي العملية.
3. من مجلد المشروع الرئيسي، شغّل الأمر مرة واحدة:

   ```powershell
   npm run dev
   ```

4. اترك الطرفية مفتوحة أثناء استخدام الموقع.
5. افتح الواجهة على `http://localhost:5173`.

لا تشغّل نسخة ثانية من الأمر بينما النسخة الأولى تعمل، إلا إذا كنت تقصد تشغيل أكثر من نسخة وأعددت منافذ مختلفة لها.

## التحقق من استجابة الـAPI والواجهة

افتح نافذة PowerShell جديدة، واترك الطرفية التي تشغّل المشروع مفتوحة. افحص الـAPI مباشرة:

```powershell
Invoke-RestMethod http://127.0.0.1:4000/api/v1/health/live
```

إذا كان الـAPI يعمل، يجب أن تتضمن النتيجة:

```text
status  service
------  -------
ok      harf-api
```

بعدها اختبر الوصول إلى الـAPI عبر وسيط Vite:

```powershell
Invoke-RestMethod http://localhost:5173/api/v1/health/live
```

إذا نجح الفحصان، فالـAPI تستجيب والوسيط يصل إليها.

## إذا ظهر أن المنفذ `5173` مستخدم

اعرض العملية التي تستمع على المنفذ:

```powershell
Get-NetTCPConnection -LocalPort 5173 -State Listen -ErrorAction SilentlyContinue |
  Select-Object LocalAddress, LocalPort, OwningProcess
```

استخدم رقم `OwningProcess` (PID) لفحص العملية. استبدل `<PID>` بالرقم الفعلي، من دون علامتي `<` و`>`:

```powershell
Get-CimInstance Win32_Process -Filter "ProcessId = <PID>" |
  Select-Object ProcessId, CommandLine
```

إذا تأكدت أن العملية تخص تشغيلًا قديمًا لهذا المشروع، فأوقف العملية المحددة:

```powershell
Stop-Process -Id <PID>
```

الأفضل إيقاف التشغيل من الطرفية الأصلية باستخدام `Ctrl+C`. لا توقف كل عمليات `node`، فقد تكون عمليات أخرى لا تخص المشروع.

## التمييز بين الأخطاء الشائعة

### `Port 5173 is already in use`

هناك عملية أخرى تستخدم منفذ الواجهة، وغالبًا تكون نسخة سابقة من المشروع. أوقف النسخة السابقة أو استخدمها بدل تشغيل نسخة أخرى.

### `connect ECONNREFUSED 127.0.0.1:4000`

لا يوجد API يستقبل على المنفذ `4000`. راجع الطرفية التي تشغّل المشروع، وابحث عن رسائل الخطأ تحت `[api]`. تأكد أيضًا أن التشغيل لم يتوقف بعد فشل Vite أو تعطل الـAPI أثناء الإقلاع.

### خطأ الاتصال بـMongoDB

قد يظهر الخطأ في الطرفية أثناء تشغيل `[api]`. هذا يختلف عن `ECONNREFUSED` على المنفذ `4000`: قد يتعذر على الـAPI الاتصال بقاعدة البيانات أثناء الإقلاع. افحص رسالة MongoDB وتحقق من عنوان `MONGODB_URI` وإمكانية الوصول إلى قاعدة البيانات.

### فشل فحص جاهزية قاعدة البيانات

يفحص المسار التالي اتصال قاعدة البيانات، بالإضافة إلى استجابة الـAPI:

```powershell
Invoke-RestMethod http://127.0.0.1:4000/api/v1/health/ready
```

إذا أعاد `503` أو أظهر أن قاعدة البيانات غير متصلة، فقد تكون خدمة الـAPI نفسها تعمل، بينما قاعدة البيانات غير جاهزة. أما فحص `/health/live` فيتحقق من أن الـAPI تستجيب، ولا يضمن جاهزية قاعدة البيانات للميزات التي تعتمد عليها.

## قراءة رسائل بدء التشغيل

عند تنفيذ `npm run dev`، راقب رسائل الطرفية:

- الرسائل التي تبدأ بـ`[web]` تخص Vite والواجهة.
- الرسائل التي تبدأ بـ`[api]` تخص خادم الـAPI.
- ظهور خطأ لدى إحدى الخدمتين قد يؤدي إلى إيقاف الخدمتين معًا.

عند الفشل، اقرأ **أول خطأ** يظهر، لا آخر رسالة فقط؛ فقد تكون الرسائل اللاحقة نتيجةً لتوقف الخدمة الأولى.

## خطوات مختصرة للتشخيص

1. أوقف التشغيل السابق بـ`Ctrl+C`.
2. شغّل `npm run dev` مرة واحدة من مجلد المشروع.
3. افحص رسائل `[web]` و`[api]` في الطرفية.
4. اختبر `http://127.0.0.1:4000/api/v1/health/live`.
5. اختبر `http://localhost:5173/api/v1/health/live`.
6. إذا فشل الاختبار الأول، راجع خطأ بدء الـAPI. إذا ظهر `Port 5173 is already in use`، افحص العملية التي تستخدم المنفذ وأوقفها فقط بعد التأكد من هويتها.
7. إذا نجح فحص الحياة وفشل فحص الجاهزية، افحص اتصال MongoDB.

## ملاحظات عن الإعدادات

- يستخدم الـAPI المنفذ `4000` افتراضيًا، ويمكن تغييره باستخدام `PORT` في `.env`.
- يحدد `APP_ORIGIN` عنوان الواجهة، ويكون افتراضيًا `http://localhost:5173`.
- يحدد `VITE_DEV_API_TARGET` وجهة وسيط Vite، ويكون افتراضيًا `http://127.0.0.1:4000`.
- لا تغيّر هذه القيم لمجرد ظهور `ECONNREFUSED`؛ تحقق أولًا من أن الخدمتين تعملان وعلى المنافذ المتوقعة.
